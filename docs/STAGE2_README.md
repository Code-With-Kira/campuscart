# CampusCart — Stage 2: Design System and Shared Layouts

**ITE 18 — Application Development and Emerging Technologies**  
**Frontend Track / Midterm**  
**Stack:** Nuxt 4 · Vue 3 · Pinia · Tailwind CSS 4 · Inter Variable · TypeScript

> **Status:** Stage 2 starter, not a finished ecommerce system. The seven-section homepage, live product data, shopping-cart logic, registration form, and real authentication are deliberately not implemented yet.

CampusCart is a **student-focused ecommerce concept** for school supplies, technology accessories, and campus merchandise. Its independent brand colors are inspired by Caraga State University Main Campus; this demo is **not presented as an official university store**.

## 1. Requirements and scope

This starter addresses the **Stage 2 shared frontend design** portion of your ITE 18 Midterm assignment:

### Components and layout mechanics

- `<NuxtPage />` renders the matched route; `<NuxtLayout />` surrounds it with the active layout.
- Files inside `app/pages/` automatically define routes.
- `definePageMeta({ layout: 'admin' })` selects an alternative layout.
- Nuxt auto-imports `app/components/layout/SiteHeader.vue` as `<LayoutSiteHeader />`; likewise for other nested layout components.
- `<slot />` in a layout displays each page's content.
- `<NuxtLink>` performs Nuxt's internal routing. It is not a normal full-page link reload.

### Why the code is split up

A shared header/footer means the same styles and navigation appear across customer pages. The admin interface is isolated from the customer shopping layout, and auth screens stay minimal. This will help scale the project without copying UI code between every page.

Tailwind v4 custom colors are declared with `@theme` in `main.css`. Examples:

```text
bg-campus-emerald
text-campus-green
bg-campus-sage
text-campus-ink
```

`cc-container` sets a shared `1280px` max width with responsive internal padding. The design uses a **mobile-first** philosophy. Primary headings use the deep emerald; green/yellow shouldn't be relied upon as low-contrast body text backgrounds.

## 6. Responsive behavior and accessibility

| Width | Expected layout |
| --- | --- |
| `320–639px` | Mobile menu button and separate accessible Cart link; single-column preview pages. |
| `640–1023px` | Compact nav with responsive spacing; footer adapts; auth layout remains centered. |
| `1024px+` | Full primary nav, account actions, horizontal admin layout. |

Keyboard-accessibility provisions:

- Skip-to-content links in layouts.
- Focus-visible outline for links, buttons, and inputs.
- Mobile menu has button label, `aria-expanded` and a controlled nav area.
- Announcement close control has an accessible label.
- `prefers-reduced-motion` disables animated scroll behavior.

**Current limitations:** Mobile menu does not trap focus or close with Escape (not a modal); full keyboard/mobile device testing is still required. Typography, spacing, and contrast should be checked manually in the final design.

| URL | Layout | Expected result |
| --- | --- | --- |

| `/products?category_name=School%20Supplies` | default | Shows “School Supplies” as selected |
| `/products?category_name=Tech%20Accessories` | default | Shows “Tech Accessories” as selected |
| `/products?category_name=Campus%20Merchandise` | default | Shows “Campus Merchandise” as selected |
| `/cart` | default | Shopping cart placeholder |
| `/login` | auth | Authentication layout preview |
| `/register` | auth | Registration layout preview |
| `/admin` | admin | Dashboard cards with dashes instead of invented data |

**Category query note:** `category_name` is a temporary route-display parameter. The approved ERD stores `categories.category_id` and `categories.category_name`; we will use a canonical `category_id` once real mock category data exists. This is explicitly a reversible Stage 2 navigation decision.

**Search note:** The header's “Search” link takes users to `/products` because an actual search input and search behavior belong to Stage 4. The link is not advertised as a functioning search field.

## 8. Homepage contract retained for Stage 3

The approved homepage must eventually contain, **in this order**:

1. Announcement bar (optional information, real offers only).
2. Navbar with CampusCart, Home, 3 categories, Search, Account and Cart.
3. Campus-themed hero with headline, supporting image and Shop Now.
4. Shop by Category — three image cards linking to categories.
5. Featured Products — name, price, image, availability and Add to Cart.
6. New Arrivals or genuine Student Deals.
7. Footer — About, contact, FAQ, policies and approved social links.

Stage 2 currently renders **1 (informational strip), 2 (nav), a *temporary* version of 3 (hero), and 7 (footer with placeholders)**. The full hero, categories, featured products, New Arrivals, and approved footer destinations must still be built or finalized. No fake offers or policies are included.

## 9. ERD alignment and current limitations

Your supplied final CampusCart ERD has **12 visible entities**: `users`, `addresses`, `categories`, `products`, `carts`, `cart_items`, `orders`, `order_items`, `payments`, `order_addresses`, `inventory_movements`, and `order_status_history`.

- The product catalog will later use `products.product_id`, `category_id`, `sku`, `product_name`, `price`, `stock_quantity`, `status` and `categories.category_name`.
- Cart state eventually connects to `carts.cart_id`, `carts.user_id`, and `cart_items.cart_id`, `cart_items.product_id`, `cart_items.quantity`.
- Current product images aren't represented in the ERD; local images will be mapped by `product_id` for Midterm, pending a decision about database storage.
- The diagram has some connections inconsistent with displayed foreign keys. These must be verified before backend integration; Stage 2 does **not** alter the ERD.
- Login/register, order checkout, inventory, and admin product updates are **not functional yet**, and the admin routes are **not protected by real authorization**.
- No real customer data or credentials are included in this project.

## 11. Troubleshooting

| Problem | Suggested fix |
| --- | --- |
| `node` or `npm` not recognized | Verify Node is installed and a new PowerShell terminal is open. |
| `npm.ps1 cannot be loaded` | Try `npm.cmd install` / `npm.cmd run dev` in PowerShell. |
| `Missing script: dev` | Make sure the terminal is in the folder containing `package.json`. |
| `@tailwindcss/vite` cannot be found | Run `npm install` in the project folder. |
| Colors/styles missing | Check `nuxt.config.ts` CSS and Tailwind plugin and `@import "tailwindcss";` in `main.css`. |
| Layout does not change | Check `app/app.vue` and the page's `definePageMeta({ layout: ... })`. |
| Nuxt welcome page appears | Confirm the correct folder is open and `app/app.vue` contains the layout/page outlet. |
| `Unknown component LayoutSiteHeader` | Confirm the exact `app/components/layout/SiteHeader.vue` path/case. |
| Localhost unavailable | Check for terminal errors and use the port Nuxt prints. |
| npm dependency conflict | Share full error; avoid using `--force` without investigation. |
